# Chronicle Risk Assessment

## 结论

当前不建议立即开启 Chronicle。Together 项目已有较完整的根目录主文档、历史计划和 Codex 项目记忆文件，短期可以先通过 `AGENTS.md + PROJECT_MEMORY.md + Skills` 承接上下文。

## 隐私风险

- Chronicle 依赖屏幕上下文，屏幕中可能出现代码、聊天、邮件、账号、token、生产数据、财务或隐私内容。
- Chronicle 需要 macOS 屏幕录制和辅助功能权限，授权范围高于普通项目文件读取。
- 屏幕中的网页、聊天或文档可能包含提示注入内容，增加误用上下文风险。
- 本地生成的记忆可能包含不该长期保存的信息，需要定期检查。
- 如果会议、客户数据、密钥排查、线上事故处理时未暂停，可能把敏感上下文纳入记忆生成过程。

## 额度使用风险

- Chronicle 会在后台运行额外代理从屏幕上下文生成记忆。
- 长时间开启会比普通 Codex 使用更快消耗额度。
- 大量窗口切换、长时间调试、频繁上下文变化会增加后台处理负载。
- 生成记忆不一定立刻可用，额度消耗和收益不完全同步。

## 缓解措施

- 默认关闭 Chronicle。
- 只在低敏任务中短时开启。
- 开启前关闭聊天、邮箱、生产后台、密码管理器和不相关文档。
- 会议、客户数据、密钥排查、生产事故处理时暂停 Chronicle。
- 完成目标后立即暂停。
- 定期检查 `~/.codex/memories/` 下生成内容。

## 启用前检查清单

只有全部满足时才建议试用：

- 当前任务不涉及密钥、客户隐私、财务、医疗、法律或生产敏感数据。
- 屏幕只保留与任务相关的低敏窗口。
- 已知道如何暂停和关闭 Chronicle。
- 接受额外额度消耗。
- 愿意事后检查生成的 memory 文件。

## 建议策略

- 短期：不开启 Chronicle。
- 中期：如果频繁需要 Codex 理解“刚才屏幕上发生了什么”，再用低敏任务短时试用。
- 长期：只有在收益明显、隐私流程成熟、额度消耗可接受后，才考虑常规使用。
