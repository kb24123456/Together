# Today Important Date Capsule Design

## 1. 结论

Today 重要日期胶囊采用“稳定锚点 + 7 天临近展示池 + 用户停留位”的设计。

- 默认显示“在一起的日子”。
- 其他生日、节日、自定义纪念日只有在未来 7 天内才进入 Today 胶囊。
- 多个日期时使用单层胶囊横向滑动切换，并显示非常轻量的分页点。
- 用户滑到哪一个日期，就暂时停留在哪一个日期。
- 临近日期当天结束或过期退出展示池后，自动回到“在一起的日子”。
- 计数方式不再依赖长按；改为点按视觉上的计数文本区域切换。

## 2. 背景

当前 Today 会展示“下一个最近到期的重要日期”。用户添加“在一起的日子”“我的生日”“对方生日”后，最新或最近的生日可能抢占 Today 胶囊，导致“在一起的日子”这个长期情感锚点被弱化。

产品主线仍是单人 Todo 效率工具，纪念日不能成为 Today 主功能。这个胶囊的定位应是轻量情感与提醒补充，而不是独立运营模块。

## 3. 目标

- 让 Today 默认稳定显示“在一起的日子”。
- 让 7 天内临近日期可被看见，但不长期干扰 Today。
- 让用户通过滑动切换多个日期，形成类似 iOS 小组件的轻量浏览感。
- 让计数方式切换更可发现，不再只依赖长按。
- 保持当前 Today 胶囊的轻量视觉，不升级成大卡片。

## 4. 非目标

- 不新增复杂的“默认日期设置”页面。
- 不让 7 天外生日或节日长期显示在 Today。
- 不修改纪念日通知规则。
- 不新增 Supabase 字段或迁移。
- 不改 `ImportantDate` 核心模型。
- 不把纪念日做成 Today 主链路。
- 不把该能力扩展到单人模式；当前仅作用于已有 pair mode 重要日期胶囊。

## 5. 展示池规则

展示池由 ViewModel 计算，不在 View 中硬编码。

### 5.1 固定锚点

- “在一起的日子”永远进入展示池。
- 实现时用 `ImportantDateKind.anniversary` 识别“在一起的日子”，不能依赖标题文案；当前创建入口标题可能是“我们的纪念日”。
- 当前管理页只允许一个 `.anniversary`，因此展示池只需要处理一个固定锚点。
- 它是首张、默认显示项和兜底项。
- 如果展示池只有它一个日期，不显示分页点。

### 5.2 临近日期

- 除“在一起的日子”外，其他重要日期只有在未来 7 天内才进入展示池。
- “最新添加的日期”不突破 7 天规则。
- 如果最新添加日期也在未来 7 天内，它排在“在一起的日子”之后。
- “最新添加”应优先使用本地持久化层或同步 DTO 中已有的 `createdAt`，不要为了排序把 `createdAt` 加进 `ImportantDate` 核心模型。
- 如果某个来源暂时拿不到 `createdAt`，只能把 `updatedAt` 作为同日排序兜底，不能把“最近编辑”误当成“最新添加”的产品语义。
- 其他 7 天内日期按距离今天从近到远排序。
- 同一天多个日期时，优先按创建时间从新到旧排序；缺失创建时间时再用更新时间兜底。

### 5.3 过期退出

- 临近日期当天可继续显示。
- 当天结束后，如果该日期不再满足展示条件，则从展示池退出。
- 如果用户当前停留位对应日期退出展示池，自动回到“在一起的日子”。
- 当前版本不维护多级历史停留栈，避免规则复杂化。
- 展示池判断必须按 `Calendar.startOfDay` 处理“今天”。现有 `nextOccurrence(after:)` 是 strictly-after 语义，年度日期在当天可能直接跳到下一年；实现时不能直接用它判断当天是否进入展示池或显示“今天”。

## 6. 用户停留位

系统记录一个轻量 UI 偏好状态，例如 `selectedImportantDateID`。

- 用户横向滑动到某个日期后，该日期成为当前停留位。
- 每次进入 Today、日期变化、重要日期更新时校验停留位。
- 如果停留位仍在展示池内，继续显示它。
- 如果停留位已不在展示池内，回到“在一起的日子”。
- 如果用户从未滑动选择过，默认显示“在一起的日子”。

该状态属于 UI 偏好，不进入 `ImportantDate` 领域模型。

## 7. 视觉与交互

### 7.1 胶囊形态

- 无论几个日期，都使用单层胶囊。
- 不露出后方叠放层。
- 只有一个日期时，不显示分页点。
- 多个日期时，在胶囊下方显示极轻量分页点。
- 分页点只做位置反馈，不作为主要点击控件。

### 7.2 滑动切换

- 整个胶囊横向区域支持滑动切换日期。
- 切换后更新当前停留位。
- Reduce Motion 开启时，切换使用无弹性淡入或直接替换，不做层叠位移动画。

### 7.3 点按行为

- 点按标题、图标或胶囊主体区域：进入纪念日管理页。
- 点按视觉上的计数文本区域：切换当前日期的计数方式。
- 不使用固定左右分区，也不写死计数区宽度。
- 计数区域根据文本内容自适应扩展触控热区。
- 当空间不足时，优先保证计数文本可读和可点；标题可以适度截断。

### 7.4 计数方式

- 支持累计天数的日期可在“累计天数”和“倒计时”之间切换。
- 不支持累计天数的日期，例如生日，只显示倒计时或“今天”。
- “在一起的日子”作为 `.anniversary` 固定锚点，新建时应默认开启累计天数能力；用户后续仍可在纪念日管理页关闭。
- 计数方式建议按日期记录，例如 `countModeByDateID`。
- 当前全局 `countMode` 可以升级为按日期偏好。
- 长按切换不再作为主交互；可以移除，避免两套交互并存。

## 8. 触控与可访问性

- 胶囊整体触控体验应符合 iOS 推荐触控尺寸。
- 计数文本区域实际可触控范围不小于系统建议的最小触控尺寸。
- 实现时使用自适应布局、padding、`contentShape`、`layoutPriority`、`minimumScaleFactor` 等方式兜底，不使用固定宽度硬编码。
- VoiceOver 需要把主体操作和计数操作表达清楚：
  - 主体：进入纪念日管理。
  - 计数：切换计数方式。
- 不把分页点作为必须点击的交互入口。

## 9. 状态与实现边界

建议新增或调整的状态：

- `selectedImportantDateID`：用户当前停留的日期。
- `countModeByDateID`：每个可累计日期的计数偏好。

建议新增 ViewModel 计算职责：

- 计算 Today 日期展示池。
- 计算排序。
- 校验当前停留位是否仍有效。
- 对日期变化和事件变化做兜底恢复。
- 为 UI 生成轻量展示候选，例如 `ImportantDateCapsuleCandidate`，携带 `ImportantDate`、`createdAt`、`daysUntilOrToday`、`isAnchor` 等展示所需信息；该类型属于 UI/ViewModel 层，不进入领域模型和后端 schema。

不建议改动：

- `ImportantDate` 核心领域模型。
- Supabase `important_dates` schema。
- 纪念日通知调度规则。
- 纪念日管理页的信息架构。

## 10. 验收标准

- 只有“在一起的日子”时，只显示单个胶囊，无分页点。
- “在一起的日子”通过 `.anniversary` 识别；标题为“我们的纪念日”时也能作为固定锚点。
- 添加 7 天外生日后，Today 仍显示“在一起的日子”。
- 添加 7 天内生日后，Today 展示池包含“在一起的日子”和生日，并显示轻量分页点。
- 生日当天显示“今天”，不会因为年度 recurrence 被算到下一年而退出 7 天展示池。
- 用户滑到生日后，Today 停留在生日。
- 生日当天结束并退出展示池后，Today 自动回到“在一起的日子”。
- 点按计数文本区域可以切换累计/倒计时。
- 新建“在一起纪念日”后，默认具备累计天数切换能力。
- 点按胶囊主体可以进入纪念日管理页。
- 小屏、长标题、动态字体下，计数区域仍可读、可点，不与主体操作重叠。
- Reduce Motion 开启时切换不使用明显弹性动画。

## 11. 设计依据

- Apple Human Interface Guidelines - Gestures：常用操作应优先使用简单、直接、易记的手势。
- Apple Human Interface Guidelines - Page controls：分页点适合表达同级顺序页面，轻量位置反馈可使用 minimal 风格。
- Apple Human Interface Guidelines - Widgets：小组件应强调 glanceable content，避免塞入过多控制。
- Apple Human Interface Guidelines - Accessibility：交互区域需要照顾触控能力差异，避免依赖隐蔽或困难手势。
