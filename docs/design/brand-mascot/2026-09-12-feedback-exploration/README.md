## 当前收敛方向：原高度横向展开

用户选择小球连续变为胶囊，明确取消下行到底部的路径。新小样为 `horizontal.html`：始终保持原球40pt高度和同一垂直中心；宽度依据单行结果测量，展开同时移向屏幕水平中心，收起沿相同几何路径反向返回。眼睛保留在右端且不拉伸；短眨眼与展开同时发生，不再先点头或另设运送阶段。展开与收回各320ms，稳定阅读约2秒，播放一次后停止。

空间取舍：当前 AppRootView 的 principal 是144×44的“待办 / 定期”，右侧为40pt球、44pt个人页按钮。居中胶囊与模式文字确实占同一区域；小样采用暂时淡出模式文字、保持布局、收回后恢复。该让位方式为具体提案，尚未接入 App。生产中还需同步处理被隐藏按钮的命中与辅助功能，用户开始导航时及时撤销提示，不能留下透明控件遮挡或误触。

承载判断：MascotVisualTransfer 现已有原窗口的非交互 overlay 与原生 toolbar anchor，具备跨锚点展示同一角色的基础，因此未发现必须先下行、增加第二颗球或重建原生导航的架构障碍。现有Rive球体是固定画板；不可直接把完整角色横向拉宽，否则眼睛一起变形。正式实现需独立控制轮廓宽度与原比例脸部，不等于现有Rive资源已支持任意宽度。

内容提案：一行操作结果、不重复任务标题；普通示例宽194pt，短结果约139pt，上限334pt（390pt示意屏左右各28pt）。长文案省略并保留完整可读标签。正式App应优先精简反馈文案；辅助功能大字号下，固定40pt高度、任意长文本完整显示、任意字号三者无法同时满足，需可读性降级策略。减少动态效果小样直接切换原位球/居中结果，不做空间运动。深色反转球与消息；网页为保证轮廓连续，对真实静态角色素材用CSS统一表面明度，不代表正式Rive改色或新动作已完成。

验证：浏览器已检查展开结果、展开中段、收回中段、长文案截断与减少动态效果状态；DOM几何显示球/胶囊始终top66、height40，展开中心x195。资源加载正常，所查控制台无错误；原型缩放错误已修正后复查。尚未完成原生App接入、Dynamic Type、命中/导航中断或真机动效验收。当前网页只验证视觉提案。

## 早期建议（已由上述选择取代）

优先考虑「01 在原位说话」：结果从小球下方展开，采用同色气泡和朝向小球的短尖端，使角色与消息处在同一个局部视野中。为消息临时腾出内容空间，因此日期与列表会下移；这属于待选择的视觉提案，不是已经批准的 App 布局变更。

「02 亲自送达」保持底部反馈，让同一颗球沿右侧下行、停在气泡旁并返回。角色身份连续，但长路径更容易打扰高频编辑。

「03 变成消息」让球到达底部后连续展开成胶囊，眼睛留在一端，文字从其身侧出现。形态联系最强，品牌表现也更强；需要重点比较用户是否觉得每次修改都过于隆重。

## 专属动作草案：报信

角色先做一次轻微点头和短眨眼确认，随后带出消息；信息出现后保持安静，文字完整出现，不逐字打字、不连续弹跳。停留后消息收回，角色回到原位置与基础状态。它是编辑成功的确认，不使用任务完成时的庆祝动作。

小样用当前真实 Idle 与 Wink 素材组合表达动作意图，姿态插值不等于已完成新的 Rive 连续眼型；选定方向后才能完成正式动作制作。深色沿用当前柔白球与深色五官，消息同步为柔白表面、深色文字。减少动态效果时统一为原位静态气泡，以位置和形状保留关联。
