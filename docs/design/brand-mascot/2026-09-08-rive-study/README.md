## v6：仍沿用的行为基线

本节记录整合前的 **26 条基础时间轴**：24 条纳入 v6 统一制作，其中 Idle_Select 是逻辑片段、Idle_Orient 是转向演示；另外 2 条 Preview / Preview_Behaviors_v5 为历史预览。上方新增 4 条后，主画板合计 30 条；此处的历史验证数字只对应当时的基础版本。

默认 **Mascot → Behavior** 为单层状态机，共 **29 个节点、112 条转场、12 个原生状态动作**。其中 26 个为动画节点，另有 Entry / Any / Exit；Pick、Resolve、FeedbackDone 属于内部调度节点。日常使用无需逐条控制这些节点，只需五种持续目标和三个反馈入口。

| 输入/行为 | 当前映射 |
| --- | --- |
| mode = 0 | 常驻：轻呼吸、眨眼、加权选择短/中/长静候、偶发左看后回正 |
| mode = 1 | 编辑：拿笔 → 书写/停笔等候 → 收笔；isTyping 只表示真实输入活动 |
| mode = 2 | 当前逾期：进入担忧 → 间隔流汗 → 恢复 |
| mode = 3 | 真实处理过程：抬手、靠手思考 → 离手、收手 |
| mode = 4 | 页面可见时长期无操作：入睡 → 打盹 → 唤醒 |
| acknowledge | 常驻点击约 0.8 秒单眨眼；已有 Body PointerDown，App 原生导航不等待动画 |
| celebrateRequested | 合法的真实完成请求；庆祝一次并清除，连续请求合并 |
| remind | 常驻时的一次轻提醒；去重、冷却和业务来源由 App 负责 |

完整接入边界见 [operation-mapping-v6.md](operation-mapping-v6.md)。mode 必须限制为 0–4；后台/不可见应暂停，不能用 mode=4 代替暂停。编辑优先于处理，处理优先于逾期，逾期优先于可见打盹。保存、取消、导航仍是原生操作；不得把动画当作业务成功信号。

### 动作与过渡

- 常驻大眼统一为 v5 球面轮廓，默认接近正面；Idle_Look 是 1.6 秒轻微左看后回正。7.6 秒 Idle_Orient 保留供观察转向，不作为常驻固定循环。
- WritingFace / SweatingFace 的已认可眼形、位置和手笔运动保持；Thinking 保留固定托手支点及先手后靠头的接触关系。
- 新增 ThinkingEnter（0.75 秒）、ThinkingExit（0.6 秒）、DozeEnter（1 秒）、CelebrateConcern（1.6 秒）和 Settle（0.2 秒）。
- Celebrate 1.4 秒、Remind 1.8 秒、Thinking 4 秒循环、Doze 4.8 秒循环、Wake 1.4 秒。其它基础片段时长沿用下方 v3 表；生产常驻眼睛已替换为球面眼。
- 编辑/处理可以打断低优先反馈；结束或中断后由 Resolve 读取最新目标，不返回过期状态。CelebrateConcern 先放松流汗表情再轻庆祝；Recover 不重新生成已隐藏的汗滴。
- Celebrate / CelebrateConcern → FeedbackDone 必须保留 **16ms 非零混合**。FeedbackDone 入场清除请求，出口同时要求片段结束及请求为 false；它仍属于庆祝反馈期间。原生模拟发现，仅增加一帧等待或立即退出会在低帧率下重播或停留，当前逻辑已修复。
- 不在 WritingExit / Wake / Settle 等离场过程中无条件清除新请求，避免漏掉目标已回到 mode=0/2 的合法完成。Host 在编辑、处理、打盹或不可见时取消待播完成；庆祝全程与冷却期不新增排队。

## v3 动作结构

沿用同一套矢量部件与已认可眼形，不增加眉毛、嘴巴、手臂或装饰元素。v3 基础共 14 条时间轴，包含展示用 Preview 与逻辑用 Idle_Select；不能将它们都算作独立表演动作。

| 时间轴 | 时长 | 行为 |
| --- | --- | --- |
| Idle | 6.4 秒单次 | 长段安静待机，低幅呼吸与眨眼 |
| Idle_QuietShort | 3.6 秒单次 | 短段安静待机 |
| Idle_QuietMedium | 5 秒单次 | 中段安静待机 |
| Idle_Look | 1.6 秒单次 | 小幅张望后回正，随后强制进入长段安静待机 |
| Idle_Select | 1 帧逻辑片段 | 两个瞬时 Pick 状态共用；选择下一段，不是可见动作 |
| WritingEnter | 0.2 秒单次 | 眼形收拢、圆手出现、笔随后落到书写位置 |
| Writing | 4 秒循环 | 两组不等速短划/长划，穿插抬笔与短停顿；另一只手轻微调整 |
| WritingHold | 4 秒循环 | 笔离开书写位置，保持专注眼形，轻微抬眼思考；等待真实输入 |
| WritingExit | 0.2 秒单次 | 笔先退场、圆手随后收起，眼形恢复 |
| ConcernEnter | 0.2 秒单次 | 察觉、眼形切换，汗滴延迟出现 |
| Concerned | 6 秒循环 | 贴脸汗滴分组滑落，中间留出安静间隔；仅一次短促身体反应 |
| Recover | 0.2 秒单次 | 汗滴消退、眼形放松恢复 |
| Acknowledge | 0.4 秒单次 | 等比轻缩至 98.2%，回弹并眨眼；不压扁球体 |
| Preview | 24.05 秒循环 | 固定编排的视觉评审序列；实际随机分支运行在 Mascot 状态机 |

全部使用 60fps。长待机呼吸仅约 0.65% 等比缩放；张望身体旋转约 1.2°，近远眼位移略有差异。书写手笔继续共用 Grip 枢轴；持续书写不叠加身体呼吸，减少笔尖漂动。

眨眼通过矩形眼形高度 86 / 75 → 6.88 / 6 → 86 / 75 收拢，眼睛的纵向缩放始终为 100%，保留闭眼圆端。

### 淡变与遮挡

表情交接先淡出原眼组，再淡入目标眼组，避免四条眼线重叠。进入混合的开头保留同一组眼形，供身体和手笔短暂对齐。

Rive 父组透明度会使半透明手露出后方笔杆，不能同时淡出全部道具。v3 保留分时遮挡约束：

- 入场：手组第 7 帧完全显示后，三段笔部件在 7–10 帧出现。
- 退出：笔在 3–5 帧隐藏，手组在 6–10 帧退出。
- 四个进出片段前 3 帧保持源眼组，3–5 帧淡出，目标眼组在第 6 帧后出现，避开 50ms 混合窗口。
- 笔迹仍是独立静态简笔路径，随动作出现/收起；尚未制作逐笔绘制。

## v3 状态契约（历史）

默认状态机仍为单层 `Mascot`，共 14 个动画状态（含两个瞬时 Pick 状态）、44 条转场，另有 Entry → Idle。画板绑定 `TogetherSphereModel.Instance`。

| 属性 | 已实现的编辑器含义 |
| --- | --- |
| mode = 0 | 静候 |
| mode = 1 | 编辑；由 isTyping 决定书写或持笔 |
| mode = 2 | 着急/逾期 |
| isTyping | 布尔；true 连写，false 抬笔等候，默认 false |
| acknowledge | trigger；mode = 0 的可见待机片段中响应一次短反馈；连续触发合并、不排队 |

`mode` 必须限制为 0 / 1 / 2。Rive 的 Body 已绑定 PointerDown → acknowledge，用于编辑器点击验证；尚未绑定 App 的任务完成、保存或导航。未来首页须保留原 Button 的 Profile 行为，导航不等待装饰动画结束。

### 随机待机

- Idle 与 Idle_QuietMedium 完成后进入 PickAfterOthers：权重 9 / 1 选择 Idle_QuietShort / Idle_Look。
- Idle_QuietShort 完成后进入 PickAfterShort：权重 4 / 5 / 1 选择 Idle_QuietMedium / Idle / Idle_Look。
- Idle_Look 完成后固定进入 Idle，保证每次张望之后至少有 6.4 秒安静片段。
- 普通待机节点不启用随机转场，以顺序保证 mode 业务切换优先，其次 acknowledge，最后自动续段；只有 Pick 节点进行加权选择，并在同帧离开。

主要路径：

- 各可见待机片段 → WritingEnter → Writing / WritingHold。
- Writing ↔ WritingHold 按输入变化短混合；离开编辑先 WritingExit，再读取最新 mode。
- 各可见待机片段 → ConcernEnter → Concerned；离开着急状态先 Recover，再读取最新 mode。
- Acknowledge 可被编辑/着急目标打断；正常播放完回 Idle。
- 四个进出动作仍设置 Exit Time 100%，各为 12 帧；普通混合为 50ms，Writing → WritingHold 为 140ms，反向为 100ms。

快速改目标采用短收束，不是任意相位立即反向。96 组相位反向模拟中，最慢在最后一次目标变化后 616.7ms 进入正确稳态，计入最终 50ms 混合约为 0.67 秒。装饰状态不应阻塞输入、保存、取消或导航；这不是 App 真机响应时延。

## MCP 续作提示

- 嵌套参数显示为 `unknown` 时读取当前 `tools/list` 原始 schema，不能猜字段。
- `createTransitions` 用 `states[].id` / `transitions[].to`；`createStates` 用 `linearAnimationName`；`renameAnimations` 用 `animationId`。
- `modifyKeyFrames` 同一调用会先添加再删除；替换整条时间轴时分开删除与添加，否则重用同一 ID 的关键帧会被删掉。写后读回核对。
- 触发条件只传 `leftComparator.viewModelPropertyId`，会创建 `triggerFired`；不要拿 trigger 与布尔常量比较。
- 关键帧缓动字段为 `interpolationType` 和 `cubicParams`。v3 使用单调 cubic (0.35, 0, 0.65, 1)；v5 的平滑源动作及球面曲线已烘焙为 linear，不能给全部采样点再加 cubic。
- 转场 duration 使用毫秒；本轮 Exit Time 的 flags = 28（启用、百分比、退出时暂停源），exitTime = 100。以读回的语义字段为准。
- 属性 ID、动画 ID、状态 ID 与具体文件绑定；续作先核实文件身份与现行数据。
- `group_editor` 创建嵌套空组时可能保留世界坐标原点；必须读取实际本地 x/y，本文件两新增组已在 Design 显式归零。
- `createShapes` 即使没有 close 命令也可能生成闭合路径；两点眼线必须读取并设置 PointsPath.closed（32）为 false，不能只看关键帧数值。
- 球面眼需固定顶点类型：`createShapes` 可能优化成 Straight / Asymmetric；本轮使用显式 cubic 顶点，读回全部 16 个均为 CubicDetachedVertex。球面轮廓必须闭合，表情弧线必须开放。
