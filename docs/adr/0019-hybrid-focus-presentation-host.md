# 首页焦点动效采用 UIKit 瞬态呈现层与 SwiftUI 内容的窄混合架构

用户确认的任务抬升、创建展开、背景景深和列表接纳均是最终可观察的视觉与行为要求，不预设实现框架。首页继续由 SwiftUI 持有业务状态、真实时间线、任务行、编辑内容、数据提交和无障碍语义；仅在详情或创建交互会话期间，由根控制器或窗口拥有的 UIKit 瞬态呈现 Host 独占可见转场。该 Host 统一持有稳定背景平面、背景命中屏障、唯一前景任务表面、来源与落点几何以及一条可暂停和反向的视觉进度；前景内容通过 `UIHostingController` 复用 SwiftUI 组件，UIKit 不接管业务状态或长期页面布局。

系统顶部 Toolbar 保留系统导航职责，但不再作为独立动画参与者；焦点期间它与时间线和根层自定义底部 Dock 一起进入统一背景平面。自定义 Dock 的 `+` 是创建表面的真实来源，创建表面从按钮直接进入稳定、键盘安全的创建焦点位，不再先停靠紧凑列表行，也不在编辑期间预留最终空位。提交成功后，列表按冻结后的真实落点让出空间，同一前景表面直接进入任务行；若落点不可见，只允许在提交后对仍处于景深状态的时间线做一次连续定位。既有任务详情从来源任务行原位抬升并严格返回，来源位置保留无身份副本的等高空位。

纯 SwiftUI 方案被拒绝作为主转场引擎，因为当前交互跨越系统 Toolbar、根 Dock、惰性时间线、键盘和列表重排，依赖多个 SwiftUI 容器与动画完成回调会重新形成可见所有权和时序冲突；完整 UIKit 重写也被拒绝，因为它会无必要地重建任务编辑、数据绑定、动态字体和无障碍能力。混合方案的代价是必须维护明确的 SwiftUI/UIKit 边界、原子可见所有权交接、Host 生命周期和真机性能验证，但它将高风险部分限制在瞬态呈现层，并以单一视觉进度满足可逆性和前后景一致性。本决策取代 ADR-0018。
